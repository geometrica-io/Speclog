# Speclog v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An extension for VS Code (and VS Code-based editors) that reads tasks from `docs/tasks`, Backlog.md and Spec Kit files across several repositories, verifies their status from git, and offers the equivalent of the ProjectManager screen (Speclog v1).

**Architecture:** npm workspaces monorepo. `packages/core` is pure TypeScript independent of VS Code (`git` via Node `child_process`): a module-by-module translation of the ProjectManager (PM) C++ core + an adapter layer + the new "Unverified" rules. `packages/vscode` is the extension host side (hosts the engine, commands, settings, status bar) + the webview UI (framework-free TS, bundled with esbuild). A typed message protocol connects the webview and the extension.

**Tech Stack:** TypeScript 5 (strict), Node ≥ 20, npm workspaces, vitest (core tests), esbuild (extension + webview bundling), `yaml` (Backlog.md front matter), `@vscode/l10n`, `@vscode/test-electron` (extension smoke test), `@vscode/vsce`, `ovsx`, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-11-speclog-design.md`. Predecessor code (to translate, read-only): `C:\Antigravity\ProjectManager\src\core\*` and `C:\Antigravity\ProjectManager\tests\*` (+ `tests\hooks\`), PM spec `C:\Antigravity\ProjectManager\docs\superpowers\specs\2026-11-08-project-manager-design.md` (Turkish).

## Global Constraints

- Product and repository are **English only**: UI strings, README, docs, code comments, commit messages. All UI strings go through `vscode.l10n.t` / `package.nls.json` so translations can be added later; v1 ships no translations.
- `packages/core` never imports the `vscode` module; its tests link only the core.
- Speclog never modifies a task file. The only write: the "Install commit-msg hook" command the user runs. The only git command that writes: `git fetch --prune origin` (only `refs/remotes/origin/*`).
- Task files are read from git, not the working tree (main-branch tip + branch-only items on unmerged branches) — for all three formats.
- Every git call: `GIT_TERMINAL_PROMPT=0`; fetch additionally `GCM_INTERACTIVE=never`, `-c credential.interactive=false`, `-c http.lowSpeedLimit=1 -c http.lowSpeedTime=60`, and unless the user set one, `GIT_SSH_COMMAND=ssh -o BatchMode=yes -o ServerAliveInterval=15 -o ServerAliveCountMax=4`; fetch timeout 60 s, others 120 s. Full ref names (`refs/heads/…`, `refs/remotes/…`), `--end-of-options`, revision lists via `--stdin`.
- Main-branch rule: a commit is on main if reachable from `origin/<d>` **or** local `<d>`; `<d>` = `origin/HEAD` target, else `main`, then `master`.
- Statuses: `open, partial, bug, verify, decision, dropped, done, onBranch, unverified`. `unverified` only for hand-written-status formats (Backlog.md, Spec Kit) while `speclog.unverifiedDone` = `"unverified"` (default); `"done"` → done + flag + Attention; `"open"` → the file's done is ignored.
- ID characters `[A-Za-z0-9._/-]`; `docs/tasks` and Spec Kit case-sensitive, Backlog.md case-insensitive. Spec Kit ID `<feature-folder>/T###`.
- Repository name = repo name in the `origin` URL (else folder name); `Task: <Name>:<id>` and `Task: <owner>/<name>:<id>` case-insensitive; per-repository settings key = `origin` URL (else absolute path).
- Settings (defaults): `speclog.roots` = `[]`, `speclog.exclude` = `[]`, `speclog.originFilter` = `[]` (empty = all), `speclog.fetch.enabled` = `true`, `speclog.fetch.intervalSeconds` = `300`, `speclog.staleBranchDays` = `7`, `speclog.unverifiedDone` = `"unverified"`. UI state in `workspaceState`; per-repository cutoffs and hidden repositories in `globalState` (nothing written to repositories).
- Extension: `extensionKind: ["workspace"]`, single universal package, publisher `geometricaio`, name `speclog`, display name "Speclog", license MIT, copyright "Geometrica.io".
- Webview: only `--vscode-*` theme variables; light / dark / high contrast; all text the same size; Content-Security-Policy allowing only local scripts; keyboard navigable.
- LF line endings; short imperative commit messages; no `Co-Authored-By` line.
- Commands: `npm ci`, `npm run build`, `npm test` (core vitest), `npm run test:ext` (extension smoke test), `npm run package` (vsix).

## Review Focus

1. **Windows paths:** repository paths / file names with spaces and non-ASCII (e.g. Turkish) characters must work with git calls and task files (Task 3, 4 tests).
2. **Large repository / slow git:** scanning an SFEA-sized repository must not freeze the UI; closing and refreshing must be able to cancel a scan (Task 10 test: a cancelled scan is not published).
3. **Backlog.md custom settings:** no `config.yml`, or custom status names ("Backlog", "Doing", "Shipped") — first/middle/last mapping must follow the config order; without config, Backlog.md defaults (Task 5 test).
4. **Same repository twice:** when a workspace folder and `speclog.roots` point at the same repository (or a worktree of it), it appears once (Task 4 test: dedupe by realpath).
5. **No git / old git:** if git is not on PATH or is older than 2.31 (no `--diff-merges=first-parent`; `--end-of-options` needs 2.30), the extension shows one clear error instead of crashing (Task 3 test: git version check).
