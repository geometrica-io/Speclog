# Reports Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A "Speclog Report" editor tab that reports a period (progress per repository and program at its
start and end, a progress curve, and the Finished / In progress / Added / Remaining / Reopened-dropped-removed
item lists), exportable as HTML, Markdown and Print / PDF.

**Architecture:** Core gets a replay of main at a past day (snapshots rebuilt from the already-read
`mainCommits` plus task files read at the replayed commit) and a pure report model built from a start and an
end `Workspace`. The extension renders the model with pure HTML / Markdown renderers (no `vscode` import,
unit-tested); the report tab is a second webview panel that shows the rendered HTML under a small control bar.

**Tech Stack:** TypeScript, vitest, esbuild, VS Code webview API, git via `child_process` (existing runner).

**Spec:** `docs/superpowers/specs/2026-11-19-reports-design.md`

## Global Constraints

- All user-visible text is English and goes through `vscode.l10n.t('...')` with a single-quoted literal; every
  key is in `packages/vscode/l10n/bundle.l10n.json` (`l10n.test.ts` enforces both). No Turkish.
- Core (`packages/core`) never imports `vscode`; renderers in `packages/vscode/src/report/` never import
  `vscode` either (like `agentPure.ts`).
- Everything is read from git, never the working tree. No native binaries, no PDF library, no new runtime
  dependency.
- Counting rule (board's): `total` = items not Dropped, `done` = items with status Done; Unverified is not
  done. Only items on main count (`branchOnly` items are outside every total).
- Days are `YYYY-MM-DD` committer dates (`CommitInfo.date`, `%cs`). Weeks start Monday. *To* is clamped to
  today. Start state = end of the day before *From*. Curve: every day for periods up to 31 days, otherwise
  at most 30 evenly spaced points (both ends included).
- Trust cutoffs and `.since` are today's values for every date.
- Commits: short, imperative, English; a `Task: REP.n` line on the commit that finishes REP.n,
  `Task-Progress: REP.n` on commits that advance it; end with
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Tests: `npm test` (vitest, core + extension units) and `npm run test:ext` (VS Code smoke) from the repo root.

## Review Focus

1. A repository with no commit on main on or before the start day (created during the period) — expected: no
   items at the start, all its items in Added, start percentage shown as "—" (total 0), no crash.
2. A `Task: Repo:Id` closing commit in repository B for an item in A, where B is not selected — expected: the
   item is still Finished in A (all repositories replayed, only the selection shown).
3. An item deleted from the task file during the period, and one dropped during it — expected: listed under
   Reopened / dropped / removed, never in totals at the end.
4. Changing the period while a long replay runs — expected: the running computation is cancelled, only the
   newest result is shown, no stale result overwrites it.
5. Item titles / notes containing `<`, `&`, `"`, `|` or backticks — expected: escaped in HTML (no markup
   injection into the webview or export) and in Markdown tables (pipes escaped).

Each line has a test in the task that owns the code: 1 → Tasks 2 and 4, 2 → Task 2, 3 → Task 4,
4 → Task 8 (`LatestRun`), 5 → Tasks 6 and 7.

    with `branches: []` (trust / since fields copied from the live snapshot), or an empty one when
    `commitAtDay` is `''`; then `resolveAll(replayed, mode)`. `error` = first repository error (`'cancelled'`
    when the signal aborts).

- Consumes: `Workspace`, `ResolvedItem` (`status.ts`), `Period`, `startDay` (Task 3).
- Produces:
  ```ts
  export interface Progress { done: number; total: number; }
  export interface ReportItem {
    repo: string; repoPath: string; programPath: string; programTitle: string;
    id: string; title: string; status: Status; isNew: boolean;
    created: string;            // item.created or ''
    closedDate: string;         // Finished: doneDate
    closedCommit?: { hash: string; subject: string }; // newest closing commit dated closedDate; absent for history-done
    progressReason?: { kind: 'onBranch' | 'branchOnly' | 'partial' | 'commit'; branches: string[]; date: string };
    change?: 'reopened' | 'dropped' | 'removed';
  }
  export interface ProgramReport { path: string; title: string; start: Progress; end: Progress; }
  export interface RepoReport {
    name: string; path: string; key: string;
    start: Progress; end: Progress; programs: ProgramReport[];
    curve: Progress[];          // one per curve day
    finished: ReportItem[]; inProgress: ReportItem[]; added: ReportItem[]; remaining: ReportItem[]; changed: ReportItem[];
  }
  export interface ReportModel {
    period: Period; startDay: string; curveDays: string[];
    endIsLive: boolean;         // end state is the board's (period ends today)
    repos: RepoReport[];        // selected repositories, in the order given
    total: { start: Progress; end: Progress; curve: Progress[] };
  }
  export function buildReport(input: {
    period: Period; start: Workspace; end: Workspace; endIsLive: boolean;
    curve: { day: string; workspace: Workspace }[];   // ascending, = curveDays
    selectedRepoPaths: readonly string[];
  }): ReportModel;
  export function percent(p: Progress): number | null; // Math.round(100*done/total); null when total = 0
  ```
  Item identity across workspaces: `repoPath` + program format + `normalizeId(format, id)`. Rules (spec Goals 4
  and "Lists" rule): Finished = end Done and start not Done; In progress = not Done at end and any of end
  status `onBranch` (only when `endIsLive`), `branchOnly` (only when `endIsLive`; reason `branchOnly`, never
  in totals), stored/status `partial`, or a commit in `ResolvedItem.commits` dated `from..to`; Remaining = other
  end items not Done and not Dropped; Changed = reopened (Done at start, not Done and not Dropped at end),
  dropped (Dropped at end, present and not Dropped at start), removed (present at start on main, absent at
  end); Added = on main at end, absent at start, also flagged `isNew` in its state list. Lists sorted by
  program path then file order (`item.line`).
